# Repo-wide comment cull

## Goal

Remove restating and prose comments across all Go files, keeping only non-obvious why, as one line each.

## Scope

- Comment convention going forward: keep a comment only for a non-obvious why (ordering constraint, protocol/platform quirk, silent cross-file coupling), compressed to one line. Doc comments are one sentence starting with the identifier. No paragraphs, no blank // continuation lines.

## Discoveries

- tools/docsgen does NOT parse Go source. It renders from docs/*.md; keydocs_test.go reads keys.Defaults() struct field VALUES (b.Keys, b.Show), not comments. So comments in internal/keys/keys.go carry no doc-generation coupling and were safe to cut.

- Comments that are genuinely load-bearing and were deliberately kept: SQLite on-disk offsets in store/sqlitefile.go (page size at 16, format versions at 18/19, varint shape); VT/DECSET sequence numbers in internal/terminal; the sshx auth note that a client tries each method NAME at most once, so agent+file signers must merge into one publickey method; the aws-ssm grandchild pipe deadlock behind proxy.go owning its stderr *os.File; Windows clipboard code-page/thread-ownership/go-vet-uintptr rules.

## Decisions

- **Decision:** Verify the pass by comparing go/scanner token streams (comments excluded) between HEAD and the working tree, rather than reading diffs.
  - **Reason:** 24 agents edited in parallel and two reported that a shared-scratchpad script collision caused one agent's python call to execute a sibling's script; diff review alone could not rule out an unintended code edit.
  - **Trade-off:** Token-stream equality proves no code change but says nothing about comment quality, which still needs human review.

## Failures

- **Approach:** First verifier reprinted each file via go/printer with Comments=nil and diffed the output; it reported 54 false positives.
  - **Lesson:** go/printer derives line breaks from token positions, so removing comment lines shifts positions and changes printed formatting. Compare token streams, not printed source, when proving a comment-only edit.

## Validation

- go build ./... — passed; go build -tags hopdemo ./... — passed; go vet ./... — clean; go test ./... — all packages ok; gofmt -l — clean; token-stream comparison across all 182 tracked .go files — identical to HEAD (zero code change)

## Remaining risks

- Comment quality was judged by 24 independent agents against one shared rule set, so tone and depth may vary between packages; a reader may still find a surviving comment too terse or a cut one worth restoring.

## Handoff

- If a package reads too bare, git diff <base_commit> -- <path> shows exactly what was removed and can be selectively restored.
