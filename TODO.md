# hop — TODO

A Windows-first TUI SSH/server manager with embedded terminal panes.
Stack: Go, Bubble Tea/Lip Gloss, pure-Go SSH (`x/crypto/ssh`), `x/vt` emulator, SQLite (`modernc`), `pkg/sftp`.

See also: [KEYBINDINGS.md](KEYBINDINGS.md).

- [ ] **Phase 3 — Tunnels / port-forwarding:** define local/remote forwards per host, start/stop with a key, show status in the dashboard. (`ssh.Client` supports `Dial`/`Listen`; reuse the existing connection.)

## 🪟 Panes & tabs

- [x] **Shell tabs:** `S` in the host list — or `alt+0` from a focused pane — opens another shell on an already-connected host (second channel, no re-handshake), shown as a tab strip. `alt+←/→` cycle, `alt+1..9` jump. `exit` closes a tab; the last one ends the session unless a browser/editor still holds the connection.
- [x] **Editor tabs:** `enter` on a file opens it in a *remote* editor (`${EDITOR:-vi}` over a second SSH channel on a pty), rendered in a hop pane with a tab strip. `alt+←/→` cycle, `alt+1..9` jump, `:q` closes a tab, `ctrl+o` back to the browser. No download — `:w` writes the real remote file. `sshx.Command` (pty + exec) is the primitive.
- [x] **Vim motions + back/forward keys:** `gg`/`G`, `H`/`M`/`L`, `ctrl+d`/`ctrl+u`, `ctrl+f` in the browser; the host list keeps only `hjkl` + the page keys (see the keymap-scope entry under UX polish). `enter`/`l`/`right` descends, `h`/`left` backs out; `left` at the browser top pops back to hop. Panes reserve `ctrl+o` and a 400 ms double-`esc`; every other key — `left` included — goes to the remote shell.

## 🖥️ Host management

- [x] **Add/edit host in the TUI:** `a` adds, `e` edits the host under the cursor via a centered modal form (`internal/tui/hostform.go`). `store.Add` (INSERT that fails on a taken alias) prevents silent overwrites; alias rename via `store.Rename` preserves visit/frecency history.
- [x] **Delete host:** `x` deletes behind a confirmation modal (`internal/tui/confirm.go`); a live session is torn down first.
- [ ] **Groups/tags UI:** the form sets `Group`/`Tags`, but the list doesn't section by group or filter by tag yet.
- [x] **Pin host to the top of the list:** `p` lifts the host under the cursor out of the frecency order into a **PINNED** section above the rest (`pinned`/`pin_order` columns, added to existing databases by an `ALTER` pass in `store.migrate`, since `CREATE TABLE IF NOT EXISTS` never touches a table that is already there); `shift+k`/`shift+j` move it inside that section, because the pinned order is the user's and not a second frecency. A new pin lands at the *bottom* of the section, so pinning one host never reshuffles the order set for the others, and `pin_order` is renumbered densely on every pin/unpin/move/delete. The sidebar grew a row model (`model.rows`, headings interleaved with hosts) that the scroll window, the scrollbar and the mouse all measure in, so a heading is a row to all three or to none; the cursor stays an index into `filtered`, so headings are never selectable. With nothing pinned the sidebar is exactly what it was — the sections take over the fixed `HOSTS` title only once they exist, rather than saying the word twice. Filtering keeps the sections — a pin outranks a match score, and the PINNED section stays in *pin* order even then, because a score has nothing to say about an order set by hand and drawing it by score would leave `shift+j`/`k` moving a host somewhere other than where it looks like it is going — and drops the heading of a section with no matches left. Paging goes through `pageCursor`, in row space: adding a row count (headings included) to a host index stepped over a host per heading on screen. `shift+j`/`k` rather than `alt` chords: `alt` never reaches hop on a default macOS terminal.
- [ ] Local file picker for the identity-file field (currently free-text; needs a local-fs adapter — `filebrowser` is remote-oriented).
- [x] **Re-import / sync `~/.ssh/config` from within the TUI:** `i` opens a one-field import card (`internal/tui/importer.go`) pre-filled with `~/.ssh/config`; `enter` upserts every non-wildcard host, `esc` closes. A first run (no hosts + a config on disk) opens it automatically, so nobody has to leave the TUI for `hop import`.

## 🔐 Connection & auth

- [x] **known_hosts:** an unknown key aborts the dial (`sshx.UnknownHostKeyError`, nothing appended) and the TUI shows a modal "NEW HOST KEY" card (`internal/tui/hostkey.go`) with the fingerprint; `y` retries via `sshx.ConnectTrusting` (appends only if the presented key matches the approved fingerprint), `n`/`esc` trusts nothing. A known-host mismatch stays a hard error.
- [x] **Private-key auth (agent no longer required):** `internal/sshx/keys.go` loads the host's `IdentityFile` (with `~` expansion) or the default `~/.ssh/id_{ed25519,ecdsa,rsa,dsa}`, and `authMethods` merges those signers with the agent's into a **single** publickey method — the SSH client tries each method name only once, so a separate agent method would swallow the attempt. Fixes connecting on macOS, where launchd always exports `$SSH_AUTH_SOCK` but the agent holds no identities until `ssh-add`. Passphrase-protected and missing-`IdentityFile` keys are reported in the "no usable authentication" error.
- [x] **Interactive auth (2FA/OTP, passwords):** `sshx.Prompter` (`internal/sshx/prompt.go`) lets the dial ask the UI a question *from inside the handshake*, which is what a `keyboard-interactive` challenge is — how a host running `pam_google_authenticator` asks for its verification code, on its own or as the second factor after `AuthenticationMethods publickey,keyboard-interactive`. `authMethods` offers publickey, then `RetryableAuthMethod`-wrapped keyboard-interactive and password, so a mistyped code re-prompts inside the same handshake. The host-key card's abort-and-replay could not be reused: a TOTP code is valid ~30 s, single-use, and rate-limited to 3 per 30 s, so a replayed dial would spend a code per attempt. The TUI side is a channel round trip (`internal/tui/authprompt.go`): the dial blocks on `Ask`, the model has one permanently-armed receiver, the card answers on a reply channel, and a second host's challenge queues behind the first. `esc` cancels, and the cancel is *sticky* (`stickyCancel`) — otherwise the client would move straight on to the next offered method and prompt again. Answers are masked unless the server sets the echo flag, and never stored: one prompt per host per run, because extra shells and SFTP are channels on the connection that already authenticated.
- [x] **End-to-end 2FA tests against a real server:** `internal/dockerenv` builds and runs an Ubuntu container with real `openssh-server` + `libpam-google-authenticator`, listening four times — code only (2222), `publickey,keyboard-interactive` (2223), password+code (2224), and both methods as alternatives (2225, the only shape that exercises `stickyCancel`, since a client that gives up on one method still has the other to try). `internal/sshx/twofactor_docker_test.go` drives the engine, `internal/tui/twofactor_docker_test.go` drives the real card and asserts a live shell comes out. TOTP is computed in-repo (`dockerenv/totp.go`, RFC 6238, no new dependency). Two things the setup needed: sshd has no option for choosing a PAM service, so the two stacks are selected by running copies of the binary named after their `/etc/pam.d` file (`SSHD_PAM_SERVICE` is `__progname`); and readiness must be the SSH banner, not a TCP connect, because Docker's port proxy accepts connections before anything inside is listening. Opt-in via `HOP_DOCKER_E2E=1` (`just test-e2e`), so CI is unaffected.
- [x] **Reconnect handling:** a dropped connection is detected, marked dead and offered back rather than leaving a pane that quietly stopped updating. `sshx.Client` now watches its own transport (`Lost()`/`IsLost()`/`LostErr()`, a goroutine parked on `ssh.Client.Wait`) *and* sends OpenSSH's keepalive probe every 15 s, giving up after three unanswered — without the probe a blackholed link (suspended laptop, dropped VPN) ends nothing and is never noticed. The TUI keeps the session (`session.dead`): the panes still hold the last screen the host drew, which is what you want to read when a link goes down. Every channel dies at once on a dropped connection, so the shell/editor exits that follow are checked against the connection (`deadConnection`) instead of being taken for `exit`/`:q` — dropping those tabs would close the session and take the reconnect offer with it. A dead pane forwards nothing and binds `r` (reconnect), `d`/`x` (drop) and `ctrl+o` (back); `r` is in the host list too, and `enter`/`s`/`S`/`f` on a dropped host all mean reconnect. `r` re-dials and restores the *shape* of the session from a `reconnectPlan` — as many shell tabs, the browser in the directory it was standing in, the half you were in dialed first so focus lands where you left it. Editor tabs are deliberately not reopened (an editor holds a buffer; reopening the file on a fresh pty would look like nothing was lost) and the status says how many were left behind. See `internal/tui/reconnect.go` and the reconnect section in [KEYBINDINGS.md](KEYBINDINGS.md).
- [ ] Deferred (not needed for current setup): ProxyJump/bastion, PuTTY session import.

## ⌨️ Terminal / UX polish

- [x] Cursor visible (reverse-video overlay at `CursorPosition`); typing lag removed (event-driven redraw); visual pass (keycap pills, `HOSTS` section, 3-state status dots incl. yellow `◐` connecting, accent selection bar, status badges).
- [x] **Settings popover:** `,` opens a floating card (`internal/tui/overlay.go` composites over the finished screen via `x/ansi`) over `internal/config` — editor, download dir, accent, open-with. Stored as JSON at `<UserConfigDir>/hop/config.json` (`%AppData%\hop\` on Windows, `~/Library/Application Support/hop/` on macOS), applied live on save.
- [ ] Cursor: respect hidden state and cursor style (block/bar/underline); optional blink.
- [x] Scrollback UI: `shift+↑` (one line) or `shift+pgup` (a page) pauses a focused shell into its history; `↑`/`↓` or `j`/`k` move a line, `pgup`/`pgdn` (or `ctrl+f`) a page, `ctrl+u`/`ctrl+d` a half, `g`/`home` to the top, `G`/`end` back to live. `esc`/`q`/`ctrl+o`/`enter`/`←` (or scrolling back to the bottom) return to the live shell. Off on the alt screen and when there's no scrollback.
- [x] **Collapsible sidebar:** `ctrl+b` hides the host list and gives the whole window to the pane, `ctrl+b` again brings it back (`model.sidebarHidden` → `listWidth() == 0`, everything else derives from it; every shell/browser/editor is resized on the toggle). Bound in every mode below the modal cards — the point of it is a focused shell — and answered once in `handleKey` rather than in four handlers. Session-only, no setting: hop opens on its host list. The costs, taken deliberately: a remote tmux never sees its `ctrl+b` prefix through hop, and `ctrl+b` is no longer a page-up motion anywhere (`pgup` is).
- [x] **Host list keymap trimmed to the step keys:** `keymap.Scope` splits the shared motion table — the SFTP browser keeps all of it (`gg`/`G`/`H`/`M`/`L`/`ctrl+d`/`ctrl+u`/`ctrl+f`), the host list keeps `hjkl`, the arrows, `pgup`/`pgdn` and `enter`. The list doesn't scroll, so the jumps landed a `j` or two from the cursor while holding nine keys hostage in the one view with commands to spend them on. Same meanings in both views, just fewer of them in the list.
- [x] **Mouse support (scroll/click) in panes and lists:** enabled through Bubble Tea's cell-motion reporting and routed by region (`internal/tui/mouse.go`): the wheel steps the host list's selection, pauses a focused shell into its scrollback (three lines a notch, exiting at the live bottom) and moves the browser's cursor; a click stands on a host or an entry, takes the keyboard for a pane the list still owns, hands it back when it lands in the sidebar (what `ctrl+o` does) and switches shell/editor tabs from their strip; a double-click within 400 ms is `enter` — connect, or open the directory/file. Every gesture is an existing binding reached by pointing, so nothing is mouse-only. The hit-testing derives from the same layout arithmetic `View` composes with, and the two row mappings run the renderers backwards (`listStart`, `tabAt`, `Browser.RowAt`) rather than guessing. A remote program that asks for the mouse gets the pointer *verbatim*: `internal/terminal/mouse.go` watches DECSET 9/1000/1001/1002/1003 and 1006 through the emulator's mode callbacks — vt's own `isModeSet` is unexported, so its `SendMouse` cannot be asked whether an event would have gone anywhere — and encodes the report itself (SGR, or X10 — xterm's own byte range, so a program that asks for the mouse without SGR still hears about the right-hand half of a wide pane; a report that cannot name the cell at all is dropped rather than aimed at the wrong one), writing it under the mutex `SendKey` uses. Cards are keyboard-only, a dropped pane forwards nothing, and `,` → **Mouse** → off gives the pointer back to the terminal (default on, the one config field whose zero value is not its default).
- [x] **Mouse text selection, and the mouse's own two defects:** taking the mouse takes the terminal's click-and-drag selection with it, so hop selects for itself — drag over a shell pane (live or paused in its scrollback) or an editor that has not asked for the mouse, and the span highlights as you go and lands on the clipboard when you let go, with the header saying how many lines. Any key, any scroll and any click elsewhere takes the highlight down. The two primitives are in `internal/terminal/selection.go` (`Highlight`, `PlainText`) and work on the *rendered* view string — one column-aware walk that skips escape sequences and counts wide runes — so the live screen, the history window and an editor pane are all covered by the same code; `internal/tui/selection.go` is the press/drag/release half. A remote program that asked for the mouse keeps it, selection included. `ctrl+g` is the escape hatch for what a per-pane selection cannot do (a span across the sidebar and a pane, or a terminal feature that wants the pointer): it hands mouse reporting back to the terminal live, and takes it back. Two defects the original mouse work left behind went with it — a pane line wider than its box made `lipgloss` *wrap* rather than clip, growing the screen past the window until the terminal scrolled hop's own header off the top (scrollback keeps each line at the width the pane had when it was pushed, so `ctrl+b` or a resize was enough to trigger it: `renderRight` now clamps width as well as height), and hop could write raw non-character bytes into a shell — the X10 cap above, plus dropping the mouse/paste shadow state when a program leaves the alt screen without switching its own modes off — done through the emulator's `AltScreen` callback, i.e. *in stream order*, because the shell's own asks arrive in the same read as the program's exit and a clear applied after the chunk threw them away, plus `strings.ToValidUTF8` on every paste.
- [ ] Narrow-terminal handling: header/footer truncation and min-size behavior.
- [x] **Copy/paste into the remote shell:** paste has no key of its own — you paste the way your terminal pastes, and hop marks it as a paste. `internal/terminal/paste.go` shadows DECSET 2004 through the emulator's mode callbacks (the mouse's arrangement exactly, and for the same reason: vt's `isModeSet` is unexported) and `SendPaste` wraps the text in `ESC[200~`/`ESC[201~` when the far end asked to be told, which is what stops vim indenting a pasted block into a staircase. The payload is sanitised either way: CRLF and LF become the CR a pty reads as Enter; unbracketed, ESC and the other C0 controls are dropped, since every byte is a keystroke to whatever is reading; bracketed, the file's own escapes go through and only the terminator itself is stripped, so a paste cannot pretend to have ended. On macOS/Linux the text arrives as one marked key event and is routed straight through (`msg.Paste` in the shell, editor and scrollback handlers — above every binding, because a clipboard holding "q" is not the key q). Windows has no marked paste at all: Bubble Tea reads console *input records* there, a paste is synthesised keystrokes, and neither Windows Terminal's `ctrl+shift+v` nor a right-click in conhost can be intercepted — so `internal/tui/paste.go` recognises the burst, holding pastable keys for 8 ms and sending them as one paste. It is deliberately conservative about the things that arrive as fast as a paste without being one: a burst counts as a paste only if it holds at least two keys and carries a newline, or runs to four characters that are not all the same — so a held `j` still moves down, a quick `dw` in vim still deletes a word, and a typed Enter (which arrives alone in its burst) is executed rather than bracket-pasted into a shell that would only insert it. A paste is dispatched once, in `handlePaste`, above every mode — every handler reads a key's *name*, and a clipboard holding "q" in the host list would otherwise quit hop. The copy half is OSC 52 — the scanner that was already watching for OSC 7 now takes a clipboard write too (with a payload cap of its own: a yank is legitimately a file's worth) and hands it to a sink the TUI installs, which writes the local clipboard through `internal/clipboard` (pbcopy / wl-copy·xclip·xsel·clip.exe / the Win32 API, since clip.exe mangles anything outside ASCII). A remote asking to *read* the clipboard is never answered. It is a channel from a remote machine to your desktop, so it is a setting — `,` → **Remote clipboard**, default on — and the popover's field list now scrolls inside the card on a short window rather than growing past it, which is what kept a seventh setting from pushing the card off a 24-row terminal.
